# Existing resolutions

Fictional demo business policy; not a real platform policy.

## HISTORY-01: Existing resolutions take precedence

An order with a completed refund or an open carrier investigation request is not
eligible for a new carrier investigation request through this procedure. The
appropriate outcome is a status update on the existing resolution. If both exist,
the completed refund takes display precedence.

A closed carrier investigation request without a completed refund requires human
review. This procedure does not support reopening a request or submitting a
second one: at most one carrier investigation request per order is permitted
across this MVP, including historical requests and requests from other cases.

A completed refund does not establish delivery or fault. An open carrier request
does not guarantee a refund or a completion date. This policy does not require a
completed carrier investigation before a refund can be authorised; refund
authorisation and execution belong to a separate, out-of-scope workflow.
